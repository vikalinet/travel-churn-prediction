## Слайд 2: Бизнес-задача

### ❓ Ключевой вопрос

Как предсказать, какие клиенты собираются уйти, чтобы предложить им персонализированные скидки и программы лояльности?

### 🎯 Цели проекта

1. **Снизить отток клиентов** на 15-20% за счёт раннего выявления групп риска
2. **Оптимизировать маркетинговые затраты** — предлагать скидки только тем, кто действительно уйдёт
3. **Увеличить LTV (Lifetime Value)** клиентов через персонализацию

### 💰 Ожидаемый эффект

- Сокращение расходов на удержание на 30%
- Рост повторных продаж на 15%
- Повышение удовлетворённости клиентов

## Слайд 3: Данные и признаки

### 📊 Датасет: Customer Travel Churn

- **954 клиента**
- **7 признаков** + целевая переменная

### Признаки:

| Признак | Описание | Тип |
|---------|----------|-----|
| **Age** | Возраст клиента | Числовой |
| **FrequentFlyer** | Часто ли летает (Yes/No) | Категориальный |
| **AnnualIncomeClass** | Класс дохода (Low/Middle/High) | Категориальный |
| **ServicesOpted** | Количество воспользованных услуг (1-6) | Числовой |
| **AccountSyncedToSocialMedia** | Синхронизация с соцсетями (Yes/No) | Категориальный |
| **BookedHotelOrNot** | Бронирование отеля (Yes/No) | Категориальный |

### Целевая переменная:
- **Target (Churn)**: 0 — остался, 1 — ушёл

### Распределение:
- ~40% клиентов ушли (высокий уровень оттока!)

## Слайд 4: Архитектура ML-системы

### 🏗️ Архитектура пайплайна

```
┌─────────────┐     ┌──────────────┐     ┌──────────────┐     ┌─────────────┐
│   Данные    │────>│    ETL       │────>│   Обучение   │────>│   MLflow    │
│   (CSV)     │     │  (pandas)    │     │   моделей    │     │  (реестр)   │
└─────────────┘     └──────────────┘     └──────────────┘     └─────────────┘
                                                                   │
                                                                   v
┌─────────────┐     ┌──────────────┐     ┌──────────────┐     ┌─────────────┐
│  Мониторинг │<────│  Evidently   │<────│  FastAPI     │<────│  Предсказание│
│  (дрейф)    │     │   AI         │     │  сервис      │     │   (Docker)  │
└─────────────┘     └──────────────┘     └──────────────┘     └─────────────┘
```

### Компоненты:

1. **ETL Pipeline** — очистка, кодирование, создание признаков
2. **AutoML** — автоматический подбор моделей (AutoGluon, H2O, Ensemble)
3. **MLflow** — логирование экспериментов и версионирование
4. **FastAPI** — REST API для предсказаний
5. **Docker** — контейнеризация и деплой
6. **Evidently AI** — мониторинг дрейфа данных

## Слайд 5: Модели и результаты

### 🤖 Сравнение моделей

| Модель | Accuracy | F1-Score | ROC AUC | Время обучения |
|--------|----------|----------|---------|----------------|
| **XGBoost** | **90.6%** | **74.3%** | **96.6%** | 0.28 сек |
| GradientBoosting | 89.0% | 69.6% | 96.5% | 1.18 сек |
| RandomForest | 88.0% | 66.7% | 94.8% | 0.10 сек |
| LogisticRegression | 80.1% | 45.7% | 82.1% | 0.03 сек |
| **AutoML Ensemble** | **89.5%** | **74.4%** | **96.5%** | 2.5 сек |

### ✅ Тестирование

- **Unit-тесты**: pytest (проверка ETL, валидация данных)
- **Интеграционные тесты**: полный пайплайн от данных до предсказания
- **API-тесты**: FastAPI endpoints
- **Покрытие кода**: >80%

### 🏆 Лучшая модель

**XGBoost** — оптимальный баланс качества и скорости

## Слайд 6: Мониторинг и CI/CD

### 📊 Мониторинг

**Мониторинг качества модели:**
- Evidently AI — отслеживание дрейфа данных (KS-тест)
- MLflow — логирование метрик и версионирование
- JSON/HTML отчёты о дрейфе

**Мониторинг инфраструктуры:**
- Docker контейнеры с лимитами ресурсов (CPU: 0.5-1 ядро, RAM: 1-2 GB)
- Логирование времени обучения
- Проверка загрузки CPU и памяти

**Результаты мониторинга:**
- Дрейф данных: **не обнаружен** (все p-value > 0.05)
