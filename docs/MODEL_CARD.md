# Model Card: travel-churn-model

Карточка модели прогноза оттока клиентов туристической компании. Структура — по
[Mitchell et al., «Model Cards for Model Reporting»](https://arxiv.org/abs/1810.03993).
Цифры в карточке пересчитаны 05.10.2026 на текущей версии модели.

## 2. Назначение

**Для чего:** оценка вероятности того, что клиент туристической компании перестанет
пользоваться её услугами, — чтобы заранее выбрать клиентов для удерживающих
предложений (скидка, персональное письмо, звонок менеджера).

**Пользователи:** аналитики CRM и маркетинга; модель встраивается через REST API
(`POST /api/v1/predict`, `/api/v1/predict_batch`) или веб-интерфейс.

**Вне назначения:**
- решения, существенно влияющие на клиента без участия человека (отказ в обслуживании,
  разные цены для разных клиентов);
- клиенты вне диапазона обучающих данных: возраст младше 27 или старше 38 лет, другие
  рынки и компании;
- выводы о причинах оттока: модель находит связи, а не причины.

## 3. Данные

**Источник:** открытый датасет Customer Travel Churn — `data/raw/Customertravel.csv`,
954 клиента. Доля ушедших — **23.5 %**.

| Признак | Значения | Кодирование для модели |
|---|---|---|
| `Age` | 27–38 лет | как есть |
| `FrequentFlyer` | Yes / No / No Record | Yes → 1, No и No Record → 0 |
| `AnnualIncomeClass` | Low / Middle / High Income | 0 / 1 / 2 |
| `ServicesOpted` | 1–6 услуг | как есть |
| `AccountSyncedToSocialMedia` | Yes / No | 1 / 0 |
| `BookedHotelOrNot` | Yes / No | **0 / 1** (так закодировал ETL; API кодирует так же) |
| `Target` | 1 — ушёл, 0 — остался | — |

**Разбиение:** 80 / 20, стратифицированное по `Target`, `random_state=42`:
763 клиента на обучение, 191 на проверку.

**Особенность данных — повторы.** Полностью одинаковых строк 507 из 954; различных
сочетаний признаков всего 419. У 143 из 191 клиента проверочной выборки (75 %) точно
такой же клиент есть в обучающей. Влияние на метрики — в разделе 4.

## 4. Метрики

**На проверочной выборке (191 клиент)** — эти цифры записаны в файл модели и MLflow:

| Accuracy | Precision | Recall | F1 | ROC AUC |
|---|---|---|---|---|
| 91.6 % | 83.7 % | 80.0 % | 81.8 % | 96.1 % |

Эти цифры **оптимистичны**: порог 0.41 подбирался на той же проверочной выборке, на
которой считались метрики, и выборка одна.

**Более осторожная оценка** — 5-кратная кросс-валидация с тем же алгоритмом и порогом,
где одинаковые клиенты не попадают одновременно в обучение и проверку (GroupKFold по
сочетанию признаков):

| Precision | Recall | F1 | ROC AUC |
|---|---|---|---|
| 72.8 % | 77.7 % | **75.2 %** | **95.5 %** |

Ранжирование клиентов по риску (ROC AUC ~0.95) устойчиво, а F1 при выбранном пороге
ближе к **0.75**, чем к 0.82. Эту оценку и стоит ожидать на новых клиентах.

**Почему F1 и Recall:** пропущенный уходящий клиент дороже лишнего предложения
удержания, поэтому порог смещён в пользу полноты, а модели сравниваются по F1.

## 5. Качество по группам клиентов

Та же кросс-валидация без повторов, порог 0.41:

| Группа | Клиентов | Доля оттока | ROC AUC | Recall | Precision |
|---|---|---|---|---|---|
| Доход Low | 386 | 27 % | 0.97 | 0.84 | 0.88 |
| Доход Middle | 409 | 7 % | 0.98 | 0.75 | 0.60 |
| **Доход High** | 159 | 58 % | **0.69** | 0.72 | 0.63 |
| Возраст 27–30 | 439 | 28 % | 0.98 | 0.85 | 0.83 |
| Возраст 31–34 | 239 | 18 % | 0.92 | 0.70 | 0.59 |
| Возраст 35–38 | 276 | 21 % | 0.94 | 0.68 | 0.65 |
| FrequentFlyer = Yes | 286 | 51 % | 0.84 | 0.76 | 0.70 |
| FrequentFlyer = No | 668 | 12 % | 0.98 | 0.81 | 0.78 |

Модель заметно хуже различает уходящих и остающихся **среди клиентов с высоким доходом**
(ROC AUC 0.69), хотя уходит больше половины из них. Для этой группы прогноз стоит
использовать с осторожностью и проверять вручную. У клиентов старше 30 лет полнота
ниже (0.68–0.70): каждый третий уходящий не будет найден.

## 6. Этические соображения

- Персональных данных (имён, контактов) в датасете нет. Возраст и уровень дохода —
  чувствительные признаки: модель не должна использоваться для того, чтобы предлагать
  разным возрастным или доходным группам разные цены или условия.
- Прогноз — повод предложить клиенту удерживающее предложение, а не основание
  ухудшить ему обслуживание.
- Неравное качество по группам (раздел 5) означает неравное число пропущенных
  клиентов: в кампаниях удержания клиенты с высоким доходом и старше 30 лет будут
  охвачены хуже.

## 7. Ограничения и рекомендации

- **Маленький датасет с повторами:** 419 различных клиентов. Перед реальным
  использованием модель стоит переобучить на собственных данных компании.
- **Узкий диапазон возраста (27–38):** для клиентов вне него прогноз — экстраполяция.
  Такие запросы мониторинг дрейфа покажет как сдвиг по `Age`.
- **Порог подобран на проверочной выборке:** при переобучении выбирать порог на
  отдельной валидационной части или кросс-валидацией.
- **Модель не объясняет прогноз:** для разговора с клиентом важнее его история, чем
  вероятность.

## 8. Мониторинг в эксплуатации

- Каждый запрос к API записывается в журнал (`runtime/monitoring/current_data.csv`);
  при ≥ 50 запросах дрейф считается по ним против обучающей выборки.
- Проверки: KS-тест (p < 0.05) и JS-расхождение (> 0.2), **PSI** по всем признакам
  (> 0.25 — дрейф). Результат — на `/drift`, в `GET /api/v1/drift/status`.
- Ежедневная проверка GitHub Actions (`drift-monitoring.yml`), уведомление в Telegram
  и письмо GitHub при дрейфе.
- Дрейф или падение качества запускает переобучение по процессу из
  [docs/MODEL_LIFECYCLE.md](MODEL_LIFECYCLE.md).
