# Жизненный цикл модели (BPMN)

Процесс от решения «нужна новая версия модели» до её работы в эксплуатации,
мониторинга и возврата к переобучению. Модель — `travel-churn-model`
(см. [Model Card](MODEL_CARD.md)).

![BPMN-схема жизненного цикла модели](model_lifecycle.svg)

- [`model_lifecycle.bpmn`](model_lifecycle.bpmn) — та же схема в формате BPMN 2.0:
  открывается в [demo.bpmn.io](https://demo.bpmn.io) (Open diagram) и Camunda Modeler.
- Схема и файл генерируются из одного описания: `poetry run python scripts/generate_bpmn.py`.

## Участники (дорожки)

| Дорожка | Кто | Отвечает за |
|---|---|---|
| Data Scientist | разработчик модели | данные, обучение, сравнение, Model Card, Pull Request, разбор дрейфа |
| CI/CD | GitHub Actions (`ci-cd.yml`, `drift-monitoring.yml`) | автоматические проверки, сборка и публикация образа, ежедневная проверка дрейфа |
| Владелец модели | ревьюер Pull Request | согласование: решение, выпускать ли новую версию |
| Эксплуатация | API на сервере + мониторинг | развёртывание, прогнозы, журнал запросов, проверка дрейфа, откат |

## Согласование: критерии на шлюзах

**«Не хуже champion?»** (п. 3) — новая версия идёт на согласование, если:
- F1 на проверочной выборке не ниже, чем у текущей версии `champion`;
- ROC AUC не ниже 0.90;
- качество по группам клиентов (Model Card, раздел 5) не ухудшилось заметно ни для одной
  группы.

**«CI зелёный?»** (п. 6) — все проверки GitHub Actions пройдены. Без этого слияние PR
не выполняется.

**«Одобрено?»** (п. 8) — владелец модели проверяет:
- изменения кода понятны и покрыты тестами;
- метрики в MLflow соответствуют заявленным в Model Card;
- в Model Card обновлены метрики, группы, ограничения и раздел «Версии»;
- номер версии в `models/best_model_improved.pkl` совпадает с версией `champion` в
  `mlflow.db` (это проверяет тест `test_registry_champion_matches_deployed_model`).

**«Работает?»** (п. 12) — `GET /api/v1/health` отвечает `model_loaded: true`, а
`GET /api/v1/models` показывает ожидаемую `model_version`.

## Что автоматизировано, а что нет

| Автоматически | Вручную |
|---|---|
| Регистрация версии в реестре MLflow и запись её номера в файл модели | Решение «не хуже champion» — сравнение в MLflow |
| Проверки CI на каждый PR | Ревью и одобрение PR |
| Сборка Docker-образа после merge, публикация при `release:` | Развёртывание на сервере и откат |
| Журнал запросов, ежедневная проверка дрейфа, уведомления | Разбор причины дрейфа и решение о переобучении |

Новая версия получает alias `champion` уже при обучении, но в ветке: `mlflow.db`
хранится в git, и до main изменение доходит только через одобренный PR. Работающее
приложение использует модель из main.

**Откат alias вручную** (если нужно вернуть прежнюю версию в реестре):

```python
from mlflow.tracking import MlflowClient
MlflowClient("sqlite:///mlflow.db").set_registered_model_alias(
    "travel-churn-model", "champion", "1"
)
```
